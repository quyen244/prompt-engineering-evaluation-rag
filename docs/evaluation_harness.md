# Source-backed evaluation harness

This harness has three explicit modes and never creates fallback questions, answers,
or metrics:

| mode | source | size | purpose |
|---|---|---:|---|
| `smoke` | checked-in project source spans | 20 | cheap gate for every change |
| `improvement` | `rajpurkar/squad`, Hugging Face `train` | 30 | compare retrieval configurations |
| `validation` | `rajpurkar/squad`, Hugging Face `validation` | 30 | untouched paired holdout |

The authoritative selection and provenance are in
[`eval_data/manifests/evaluation_manifest.json`](../eval_data/manifests/evaluation_manifest.json).
The repository does not commit downloaded Hugging Face data. At runtime the loader:

1. reads the pinned dataset revision/license/language from the Hugging Face metadata API;
2. requests only the bounded rows named by the manifest from `datasets-server/first-rows`;
3. verifies each immutable row ID and SHA-256 canonical-row hash;
4. fails if the API, row, answer, or checked-in project source is missing or changed.

The two Hugging Face selections are disjoint. SQuAD provides real questions, contexts,
and answer spans; no question or answer is generated by this project.

## Running an evaluation

The application supplies a LangChain retriever; the harness does not implement or
silently replace one:

```python
from src.eval.dataset import load_manifest
from src.eval.runner import EvalConfig, mode_cases, run_eval

cases = mode_cases("smoke")                 # exactly 20 project cases
report = run_eval(EvalConfig(name="baseline", top_k=5), cases, my_retriever,
                  mode="smoke")
```

For improvement/validation use `mode_cases("improvement")` and
`mode_cases("validation")`. Network/API errors are intentional hard failures. Every
run writes one JSONL file under `eval_data/results/` and appends document retrieval and
run-completion events to `eval_data/experiment_history.jsonl`; history is append-only.
`paired_compare(left, right)` compares the same case IDs without unpaired averages.

Metrics are deterministic binary-relevance Hit Rate, Precision, Recall, MRR, and nDCG
in `src/eval/metrics/retrieval.py`. Retrieval IDs must come from LangChain Document
metadata (`document_id`, `doc_id`, `id`, or `source`); a document without a stable ID
fails rather than receiving an invented ID.
